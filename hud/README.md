# Auto Tournament HUD addon (`at_hud`)

The Panorama layouts behind Ready Up's in-game HUD. The server spawns a `custom_hud_layout`
entity that points at one of these layouts, and players render it from this Workshop addon.
Plan and background: Vikunja #428.

This is the P0 spike: two hand-written layouts. `at_hello` is the smallest possible proof; `at_kit`
is the real HUD card, so it ships in the first publish. The component compiler that generates these
files comes in P2.

## Using it from the server

Set `m_strLayout` on the `custom_hud_layout` entity to the **source** path, extension included:

```
panorama/layout/custom_game/at_hello.xml
```

Not `at_hello`, and not the compiled `.vxml_c` name. Both render nothing and log nothing.

| Panel id | What the server does with it |
|---|---|
| `at_hello` | the card. Add class `hidden` to hide it. Visible by default. |
| `at_hello_text` | the label. Set dialog variable `text`. |

## `at_ui`: the clickable HUD (buttons, v2)

```
panorama/layout/custom_game/at_ui.xml
```

Design: the canvas's "Buttons (v2)" page. Build plan and test list: `BUTTONS-PLAN.md`. Two panels
with the same blocks: `ui_card` (bottom right, over the player model in the buy menu) and `ui_mid` (centre, just above the bottom HUD).
The slots and classes are listed at the top of `tools/gen_ui.py`.

Server code doesn't write these slots itself. It calls `readyup.hud.v1` `screen(slot, spec, ...)`
(`core/include/readyup/hud_iface.h`): a whole screen as `key=value` lines, listed in
`plugins/hud/hud_screen.h`. hud.so turns that into texts and classes, plays the leave and enter
animations, and owns the cursor. A button click runs the button's chat command as if the player
had typed it.

Try it without a match: `.dev` in chat lists every screen to click; `.ru hudkit tour` steps through them (`28` or a name holds one; `every 10`; `pause`, `next`,
`back`, `stop`); `ru hudkit demo <screen> [slot]` shows one (`ru hudkit demo` lists them); or
`ru hudkit screen <slot> title=Hi;btn=OK|green||.r;mouse=on`.

### Utilities ("Tailwind for CS2")

Every look the HUD can have ships in `styles/at_ui.css` once; the server picks per screen, so a new
look needs no publish. In the spec:

| key | what | values |
|---|---|---|
| `enter=` | how it arrives | `open` `flip` `alert` `slide` `slide-left` `pop` `zoom` `fade` `rise` `drop` `none` |
| `exit=` | how it leaves | `fade` `close` `slide` `slide-left` `shrink` `drop` `rise` `flip` `none` |
| `cls=` | utilities on the panel | motion `speed-fast` `speed-slow` `delay-1..3` `flash` `flash-twice` `no-flash`; glass `glass-1..3`; surface `bg-soft` `bg-solid` `bg-clear` `edge` `round-s` `round-l` `no-line` `no-brand` `no-wash` `no-px`; size `w-280` `w-340` `w-420` `w-520` `w-640` `w-760` `w-fit` `pad-s` `pad-l`; place `at-right` `at-low` `at-center` `at-top` `at-left` |
| `cls.<part>=` | utilities on one part (`brand kind title sub hint timer counter teams confirm lines cmds buttons close flow b0..b7`) | text `text-xs` `text-s` `text-m` `text-l` `text-xl` `text-2xl` `bold` `normal` `upper` `mono` `left` `center` `right`; colour `tc-ink` `tc-dim` `tc-faint` `tc-acc` `tc-live` `tc-warn` `tc-ban` `tc-ct` `tc-t`; `breathe` `blink` `hide`; buttons `pulse` `glow` `btn-s` `btn-l` |
| `color=` | accent | `acc` `live` `warn` `ban` `muted` `ct` `t` |

Defaults: the card slides, the ready pill pops, a decision flips, red alerts flash, the rest opens;
each leaves the way it came. Example: `enter=drop;exit=rise;cls=at-top edge glass-3;cls.title=text-2xl tc-live`.

## `at_kit`: the Auto Tournament HUD

```
panorama/layout/custom_game/at_kit.xml
```

Generated by `hud/tools/gen_kit.py` (fixed slots); edit the generator, not the XML. Design, every
event and a playable walk through a match: [HUD kit canvas](https://claude.ai/artifact/Nnt5WzmHAQbt8bXpoYKv97).
`ru hudkit kit <state>` shows each state in game (welcome notready ready everyone knife live
damage pause pause2 missing end endlost next off).

Three elements, **one shown at a time**, nothing while players fight:

| Element | Where | For |
|---|---|---|
| `at_card` | left, above the chat | routine information (welcome, ready, round damage, next map) |
| `at_mid` | centre of the lower half | moments everyone must see (everyone ready, knife pick, live, pauses, a team missing) |
| `at_end` | full screen, world blurred | the leaderboard when a map or series is over (20 s, then the card) |

Common classes: `on` shows an element; `c-live` / `c-warn` / `c-info` / `c-ban` / `c-muted` set its colour.
The game adds `HUD_BUYMENU_VISIBLE` while the buy menu is open; card and centre hide then.

**Card** (`at_card`): header `at_kind_a/b`, `at_text_a/b` (two layers that roll: write the new text
into the `old` one, then swap `cur` / `old`). Bodies by class: `b-rules` (`at_r0..2_k/_v`),
`b-line` (a sentence, below), `b-dmg` (`at_d0..4_name/_given/_taken/_hp`, rows `hit` `big` `took`
`dead`), `b-bar` (`at_s0..9` class `fill`, `at_pct`). `chat` shows "Press Y to chat"; `nudge` pulses.

**Sentences** (`at_p0..4` on the card, `at_mp0..4` in the centre; text in `<id>_t`): up to five
parts. Part classes: `hide`, `bold` (+ `c-live` / `c-ban`), `cmd` (+ `main` / `warn` / `side-ct` /
`side-t`). Only what the player types is a `cmd`; labels are plain text.

**Centre** (`at_mid`): `at_mkind`, `at_mtext`, `at_msub`, `at_mtimer` (top right), `at_mcounter`
(bottom right), unpause rows `at_mc0..1_team/_state` (row class `ok`), commands `at_mk0..3_l` (label)
+ `at_mk0..3_c` (command; slot class `gone`). Shown parts by class: `has-kind` `has-sub`
`has-confirm` `has-parts` `has-cmds` `chat` `has-timer` `has-counter`; `go` runs the orange wipe once.

**End** (`at_end`): `at_e_head`, `at_e_how` (class `how`), `at_e_ta/_tb` teams, `at_e_sa/_sb`
scores, `at_e_where` (bottom left), `at_e_next` (bottom right), team headers `at_ea_name` /
`at_eb_name`, rows `at_e{a|b}{0..4}` with `_n _k _d _a _g _r _s _h` (name K D A DMG ADR KAST HS),
row classes `me` (the viewer, by platform name) and `mvp`. End classes `won` / `lost` / `draw`.

Copy rules: short and visual, say it once; only typed commands in a box; short commands (`.r`
`.ur` `.p` `.up` `.tac` `.ct` `.t`; `.p` is the tech pause, `.tech` is never shown); platform display names, never "you" in lists;
countdowns as seconds, `(45)`.

## Rules for layouts

- Only `Panel`, `Label`, `Image` and `Button`. Anything else and the client refuses the whole layout
  (`[custom_hud] Layout contains disallowed panel type`).
- No `id` on the root panel. The compiler rejects it. Put ids on children.
- `hittest="false"` on anything that shouldn't take the mouse.
- No inline `style=""`, and quote `@keyframes` names (`@keyframes 'fade'`). Either one makes the
  layout fail to load with no error.
- `@keyframes` on `transform` don't run. Use a `transition` triggered by a class.
- Images are CSS backgrounds (`background-image: url("s2r://…vtex")`, `background-size: contain`),
  never `<Image>` with `scaling` or a `.vsvg`. Our own `.vtex` files must be BGRA8888; DXT5 renders pink.
- Width and height can't animate. Opacity, position (`transform`) and colours can, through
  `transition`. `@keyframes` only for opacity.
- Panorama caches layouts for the whole session. Restart the game after a change, and republish
  the addon before players see it.

More in [cs2-ui-kit's GOTCHAS.md](https://github.com/nvmxre/cs2-ui-kit/blob/master/docs/GOTCHAS.md) (MIT).

## Build (Windows)

You need Counter-Strike 2 with **Counter-Strike 2 Workshop Tools** (Steam › CS2 › Properties › DLC).
You'll know they're installed when a `content` folder sits next to `game` in the CS2 folder.

```bash
powershell -ExecutionPolicy Bypass -File hud/build.ps1
```

The script finds CS2 through Steam's library folders (pass `-Cs2 "<folder>"` to override), copies the
sources into `content\csgo_addons\at_hud\panorama\…`, runs `game\bin\win64\resourcecompiler.exe -i`
on each file, checks the compiled files landed in `game\csgo_addons\at_hud\panorama\…`, and deletes
the tool caches (`_bakeresourcecache`, `tools_thumbnail_cache.sqlite3`, …) so they don't get uploaded.

To test on your own client without the Workshop, copy the two compiled files into
`game\csgo\panorama\layout\custom_game\` and `game\csgo\panorama\styles\custom_game\`, then restart CS2.

## Publish (Windows)

The first upload creates the Workshop item. Later uploads update the same item.

1. Run `hud/build.ps1`.
2. Start **Counter-Strike 2 Workshop Tools** from Steam (CS2 › Launch › Workshop Tools, or
   `cs2.exe -tools`). CS2 can't be running at the same time.
3. Pick `at_hud` in the addon list and launch the tools.
4. Open the **Workshop Manager** and choose **New** (first time) or select the existing item (updates).
5. Fill in:
   - Title: `Auto Tournament HUD`
   - Description: `HUD layouts for Auto Tournament / Ready Up servers. Your game downloads this when you join.`
   - Visibility: **Unlisted** (servers can download unlisted and public items, not private/friends-only)
   - Preview image: any 512×512 JPG/PNG
6. Publish and accept the Workshop agreement if Steam asks. The item id is the number in the
   item's URL (`steamcommunity.com/sharedfiles/filedetails/?id=<id>`).

After publishing, a new item or update is available to its author at once, but game servers and
other anonymous downloads only get it after Steam finishes processing it, which can take hours.
Check with:

```bash
steamcmd +login anonymous +workshop_download_item 730 <id> +quit
```

"Access Denied" means Steam hasn't finished yet. It's not a server bug.

Later (P2): publish from a script with `steamcmd +workshop_build_item <vdf>` instead of the GUI.
